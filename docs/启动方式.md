# 前端启动方式（dev / 生产）

> 前端项目目录：`D:\code_work_space\llm\huice\008\harness-deep-agents-ui`
> 后端（LangGraph 2026 服务）在另一个仓库 `D:\code_work_space\llm\nl2sql`，前端通过界面「设置」里的 Deployment URL（`http://localhost:2026`）连接它，不在这里启动。

## 开发模式（日常开发用）

```bash
npm run dev
```

- 地址：http://localhost:3000
- 特点：热更新（改代码秒刷新）、左下角有 Next.js「N」开发工具按钮、有错误浮层
- 脚本：`cross-env NODE_OPTIONS='--max-old-space-size=4096' next dev`

## 生产模式（查看效果 / 部署用）

```bash
npm run build      # 先构建生产产物到 .next
npm run start      # 再启动生产服务
```

- 地址：默认 http://localhost:3000；如果 dev 还在跑会撞端口，用 `npm run start -- -p 3001` 换端口
- 特点：无「N」按钮、代码压缩优化、加载快；改代码必须重新 `build` 才生效
- 脚本：`next build` / `next start`

## 注意事项

1. **别同时 build 和 dev**：`next build` 会覆盖 `.next` 目录，而 dev server 也在用它。
   - 要么「先停 dev 再 build」，要么「build 完重启 dev」。

2. **`next.config.ts` 当前是临时状态**：为了绕过一批 DLP 加密行遗留的 `@ts-expect-error` 类型错误，临时加了
   ```ts
   typescript: { ignoreBuildErrors: true }
   ```
   - 留着它 → `npm run build` 能直接过（但跳过类型检查，可能藏掉新错误）。
   - 想恢复干净类型检查 → 先解决 DLP 遗留错误，再删掉这段配置。
   - 只走 dev 开发时这段配置不影响。

3. **两条命令都在前端目录下执行**，后端 2026 服务单独在 nl2sql 仓库启动，二者互不影响。
